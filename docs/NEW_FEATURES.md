# Новые функции Materials Data Pipeline

Сбор сведений производителей строительных материалов, корпус технических и нормативных документов для будущего NLP-модуля и отдельный слой коммерческих предложений для ИАС.

Текущая версия: 0.2.0. Реализованы адаптер каталога ТЕХНОНИКОЛЬ, извлечение применимости и характеристик, загрузка PDF, импорт нормативных HTML/PDF, экспорт JSONL, формат и сравнение предложений, схема PostgreSQL и очередь загрузки документов. Старый CLI и JSON-поля сохранены.

## Границы слоёв

1. **Производители:** исходные характеристики, назначение, монтаж, хранение, ограничения и документация. У каждого факта есть источник и место извлечения.
2. **NLP:** получает тексты, страницы, символьные позиции, исходные формулировки и кандидаты фактов. Интерпретация применимости и нормативных требований выполняется последующим NLP/экспертным этапом.
3. **Продавцы:** отдельные наблюдения цены, наличия и условий поставки с городом, магазином и координатами. Данные продавца не изменяют технические сведения производителя.
4. **ИАС:** сопоставляет исполнение, задачу, условия применения и проверенные требования; сравнивает стоимость нужного количества.

Понятия «материал подходит», «соответствует ГОСТ» и «норма обязательна» автоматически из упоминаний не выводятся.

## Установка

Python 3.10+:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -e .
.venv\Scripts\python -m materials_pipeline --help
```

Далее `python` означает интерпретатор выбранного окружения. Для PostgreSQL установите `python -m pip install -e ".[postgres]"`.

## Каталог производителя

```powershell
python parser.py --category https://www.tn.ru/catalogue/montazhnye-peny/ --limit 5 --max-pages 20 --out output/foam
python parser.py --category https://www.tn.ru/catalogue/mineralnaya-izolyatsiya-dlya-chastnogo-domostoeniya/ --limit 5 --out output/insulation
```

Эквивалентная точка входа: `python -m materials_pipeline catalogue -- --limit 5`.

Результаты: `materials.json`, `materials.txt`, `html_cache/`. Два процесса по умолчанию; незавершённая задача переназначается при падении процесса или тайм-ауте. Обход пагинации ограничивается `--max-pages`, число товаров — `--limit`. `crawl_truncated` указывает, что лимит страниц помешал добрать товары.

В JSON добавлены:

- `material_id`, `identifiers`, `category_profile`;
- `sections`: исходные тексты описания, применения и условий;
- `applicability`: фрагменты с аспектом, исходным текстом и `interpretation_status=requires_nlp`;
- `properties`: исходное значение, число для однозначного скаляра, единица, критерий, метод испытания;
- `documents`: ссылки из `href` и `data-href`, включая PDF с query-параметрами;
- `regulatory_references`: упоминания стандартов со статусом `unverified`;
- `evidence`: URL, SHA-256 HTML, XPath, цитата и версия извлечения.

Температура нанесения и эксплуатации не объединяются. Диапазоны, сложные значения и условия сохраняются исходным текстом. Единицы не пересчитываются без определённого правила. Профили предусмотрены для монтажных пен и минеральной теплоизоляции; неопределённая категория остаётся без профиля.

## Документы и NLP-корпус

```powershell
python -m materials_pipeline documents --materials output/foam/materials.json --root corpus --max-documents 10
python -m materials_pipeline export-nlp --root corpus --materials output/foam/materials.json --out output/nlp.jsonl
```

Загрузчик принимает только HTTPS-адреса из списка источника, проверяет перенаправления, MIME и размер до 32 МиБ. Есть кеш и общий интервал запросов по источнику. Для обновления используйте `--refresh`.

Общий ограничитель каталога и документов хранится в `.materials_network/`. При нескольких запусках/контейнерах задайте общий `MATERIALS_RATE_LIMIT_ROOT`; локальная конфигурация должна использовать один общий каталог. По умолчанию интервал — 2 секунды. Это ограничитель частоты, не ограничитель числа одновременно выполняющихся запросов.

Корпус:

```text
corpus/
  raw/<sha256>          неизменённые исходные файлы
  requests/*.json       HTTP-метаданные и время фактической загрузки
  documents/*.json      страницы, текст, метаданные и проблемы качества
  links/*.json          связи материалов с общими документами
```

Импорт предоставленного файла:

```powershell
python -m materials_pipeline import-document path/to/document.pdf --url https://source.example/document.pdf --kind normative_document --metadata path/to/metadata.json --root corpus
```

`--url` при локальном импорте — заявленное происхождение, а не подтверждение официальности. Исходный файл сохраняется до регистрации результата; повтор идентифицируется по виду, URL и хешу содержимого. Общая инструкция может быть связана с несколькими материалами.

PDF обрабатывается постранично через pypdf. Страницы без извлекаемого текста получают `needs_ocr`; встроенного OCR пока нет. Структура PDF-таблиц и координаты ячеек не восстанавливаются: исходник и извлечённый текст сохраняются, `table_structure_not_verified` сообщает об ограничении. HTML декодируется как UTF-8.

JSONL содержит отдельные типы записей: `material_metadata`, `catalogue_chunk`, `document_metadata`, `document_chunk`, `property`, `applicability_statement`, `regulatory_reference`, `material_document_link`. Запись `document_metadata` сохраняет сведения и OCR-статусы даже у полностью сканированного документа без текста. Экспорт выполняется потоком, без накопления всего корпуса в памяти. Для чанков сохранены `page`, `start_char`, `end_char`; позиции относятся к тексту соответствующей страницы, для каталога — раздела. `text == page_text[start_char:end_char]`. Свойства и применение не подменяют исходный текст.

Контракт и следующий этап NLP описаны в [docs/DATA_CONTRACT.md](DATA_CONTRACT.md).

## ГОСТ, СП, СанПиН

```powershell
python -m materials_pipeline sources
python -m materials_pipeline registry config/registry_manifest.json --root corpus --download-text
python -m materials_pipeline collect config/normative_manifest.example.json --root corpus
```

Команда `registry` извлекает карточки ГОСТ/СП: обозначение, область применения, даты, замены, заявленный статус, фрагменты-основания и прямые PDF-ссылки. Карточки сохраняются отдельно в `corpus/registry/` и экспортируются как `normative_registry_card`. Карточка реестра не считается полным нормативным текстом; если PDF отсутствует, фиксируется `full_text_status=not_found`. Начальный манифест содержит официальные карточки ГОСТ Р 59985-2022 и СП 50.13330.2024, а не утверждение об их достаточности для всех задач.

Сбор выполняется по явному манифесту, а не неограниченным обходом всего интернета. В каждой записи: `source`, `url`, `kind=normative_document`, `metadata`. Для ГОСТ, СП и СанПиН используйте соответствующие официальные источники и проверенные URL файлов или страниц с текстом.

В allowlist включены Росстандарт, Российский институт стандартизации, Минстрой, ФАУ «ФЦС», портал официального опубликования и Роспотребнадзор. Это список разрешённых источников загрузки; адаптер карточек реализован для Росстандарта. Это не заявление о готовности общего адаптера поиска или наличии свободного доступа ко всем текстам.

Пример СанПиН в манифесте указывает на исходную публикацию и не подтверждает актуальность редакции. Веб-страница публикации может требовать отдельной ссылки на PDF: для корпуса нужен именно полный текст. Если автоматический доступ отсутствует, используйте импорт предоставленного файла. Отдельный `config/normative_manufacturer_copies.json` содержит прямую PDF-ссылку из библиотеки производителя: такая копия явно помечается `manufacturer_hosted_copy`, её редакция не считается проверенной.

Для норматива сохраняются обозначение, тип, редакция, даты, изменения, замены, заявленный статус и его основание. Проверенный статус остаётся `unverified`, обязательность — `not_assessed`. Номера пунктов и ссылки извлекаются как кандидаты. Полнота текста, актуальность редакции, смысл требований, условия и исключения требуют последующего контроля. Автоматической юридической оценки нет.

## Предложения продавцов и география

Адаптеры сайтов ОБИ, Лемана ПРО и других продавцов в эту версию не входят. Подготовлен общий контракт наблюдения и импорт JSON, чтобы подключать сбор цен отдельно от технических данных.

```powershell
python -m materials_pipeline offers-import config/offers.example.json --out output/offers.json
python -m materials_pipeline offers-compare output/offers.json --material-id MATERIAL_ID --variant-id VARIANT_ID --city Москва --quantity 10 --unit m2 --lat 55.75 --lon 37.62 --radius-km 20 --out output/comparison.json
```

Пример предложения синтетический, с неподтверждённым сопоставлением и старой датой; он специально не попадёт в рекомендации.

Для подтверждённого сопоставления нужны `material_id` и `manufacturer_variant_id`: толщина, размеры, состав и прочие существенные признаки исполнения должны быть проверены отдельно. Парсер пока не создаёт универсальные идентификаторы исполнений автоматически. Фасовка продавца учитывается через `pack_quantity` и `quantity_unit`.

Сравнение требует одинаковых исполнения, города, валюты и единицы, цены с НДС, подтверждённого наличия и свежего наблюдения (по умолчанию до 24 часов). Рассчитывается целое число упаковок, учитываются минимальная партия и известный остаток. Цена за единицу и полная стоимость нужного количества сохраняются отдельно.

`district`, `store_id`, адрес и координаты сохраняются в наблюдении. Фильтрация реализована по городу и радиусу от координат; расстояние по прямой, не по маршруту. Для фильтра по текстовому полю района есть `--district`. Параметр `--include-nearby` вместе с координатами и радиусом включает магазины соседних городов в заданном радиусе. Административные границы районов и зоны доставки не вычисляются.

По умолчанию сравнивается стоимость товара. Для сравнения с доставкой используйте `--delivered --delivery-destination ID_ИЛИ_АДРЕС`: у предложения должна быть известная цена доставки именно к этому назначению. Неизвестная доставка не считается бесплатной. Масса, площадь и объём не пересчитываются друг в друга автоматически.

## PostgreSQL и постоянная очередь

```powershell
$env:DATABASE_URL = 'postgresql://materials:YOUR_PASSWORD@localhost:5432/materials'
python -m materials_pipeline db-init
python -m materials_pipeline db-import --root corpus --materials output/foam/materials.json
python -m materials_pipeline enqueue config/normative_manifest.example.json --run-id norms-001
python -m materials_pipeline queue-worker --agent-id agent-a --root corpus
```

В другом терминале запустите `agent-b` с теми же БД, `--root` и общим ограничителем запросов. Очередь сейчас обрабатывает задачи загрузки и извлечения документов. Каталог работает через прежний локальный supervisor; весь пайплайн ещё не переведён на постоянную очередь.

Схема: документы и их версии содержимого, снимки материалов, связи с документами, наблюдения предложений, задачи. Предметные записи сохраняют JSONB-контракт; отдельные таблицы нормализованных характеристик и проверенных требований можно добавить после стабилизации NLP-схемы.

Очередь использует `FOR UPDATE SKIP LOCKED`, аренду, heartbeat и новый токен попытки. Просроченные задачи подхватывает любой агент; старый токен не может завершить задачу. Запись документа и успех задачи фиксируются в одной транзакции. Повторные задания в одном `run-id` не создают дублей. Исходные файлы должны быть доступны всем агентам. Обновления содержимого требуют нового запуска с `refresh=true` в записи манифеста.

Docker Compose описывает PostgreSQL и два агента с общим томом. Создайте `.env` по `.env.example`, задайте пароль, затем:

```powershell
docker compose up --build -d
docker compose run --rm agent-a enqueue /app/config/normative_manifest.example.json --run-id norms-001
```

Инициализация БД при первом создании тома выполняется автоматически. Для уже существующей БД выполните `db-init`. Сейчас доступна начальная идемпотентная схема v1; полноценный механизм последующих миграций ещё не добавлен. В Docker общий корпус находится в `/data/corpus`; не смешивайте его с локальным каталогом `corpus` без явного подключения общего тома.

## Проверки

```powershell
python -B -m unittest discover -s tests -v
```

Проверяются исходные характеристики, применение и хранение, `data-href`, пагинация, настоящий сбой дочернего процесса, PDF/HTML, OCR-статус, версии, происхождение, символьные позиции NLP, связи общих документов, сравнение упаковок, география, доставка и исключение неподтверждённых предложений.

Дополнительные PostgreSQL-тесты включаются только на отдельной тестовой БД с `RUN_POSTGRES_TESTS=1` и `DATABASE_URL`. Они создают изолированную временную схему.

## Дальнейшие этапы

- NLP-извлечение применимости, сложных свойств и нормативных требований с проверяемыми фрагментами-основаниями.
- OCR сканов и восстановление таблиц с координатами и сносками.
- Автоматическое обнаружение нормативных документов, изменений и проверка полноты редакций.
- Второй производитель и более точная идентификация исполнений.
- Источники цен продавцов с корректным выбором города, магазина и условиями доступа.
- Перевод обхода каталога на постоянные задачи, расписание и метрики.
